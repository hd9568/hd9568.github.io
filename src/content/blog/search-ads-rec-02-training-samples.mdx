训练样本决定了模型究竟在学习什么。相同网络放在“曝光后是否点击”和“下一次交互物品是否为这个候选”两种数据上，输出就具有不同含义。模型公式里的 `x、y` 很简洁，构造它们却需要事件关联、时间窗口、缺失值和采样规则共同配合。

本篇以曝光点击任务为主线，延伸到转化和召回。所有时间例子都用于说明规则；公开数据中是否具备这些字段，需要逐项检查。

## 1. 先确定一条样本代表什么

“用户—物品—标签”还不足以定义样本。用户可能一天内多次看到同一物品，点击发生在第二次曝光，购买又发生在第三天。若只用用户和物品连接日志，就可能把同一个点击标到多次曝光上。

| 样本单位 | 一行数据的含义 | 常见标签 | 必须保留的关联信息 |
| --- | --- | --- | --- |
| 曝光 | 某次请求中实际展示一个物品 | 窗口内是否点击 | impression_id、request_id、位置、曝光时间 |
| 点击 | 一次已发生的点击 | 归因窗口内是否转化 | click_id、曝光关联、点击时间 |
| Query—文档 | 某次查询与一个候选的配对 | 相关性等级或交互 | query/request 分组、候选来源、标注状态 |
| 用户状态—目标物品 | 某个时刻的历史预测之后的交互 | 目标物品 ID | 历史截止时刻、目标时间、可用物品集合 |

曝光的定义本身也要一致：候选已返回、界面已渲染、进入可视区域、达到可见时长阈值，可能对应不同事件。客户端发送失败会让“没有曝光日志”混合多种情况。应把采集定义写进数据说明，避免离线将接口返回量当成实际可见曝光量。

一种曝光训练记录可以包含以下字段：

| 字段组 | 示例字段 | 用途 |
| --- | --- | --- |
| 主键 | impression_id、request_id、item_id | 去重、事件关联与请求分组 |
| 预测条件 | user_id、query、device、position | 构造输入并记录旧策略条件 |
| 时间 | event_time、available_time、snapshot_time | 恢复预测时可得的信息 |
| 策略 | model_version、recall_source、experiment_id | 解释曝光由何种策略产生 |
| 标签 | click、conversion、label_status | 区分负例、正例和待成熟记录 |
| 采样 | keep_probability、sample_weight | 说明保留机制及训练权重 |

ID 是关联键，不代表都应直接作为模型输入。request_id 可以帮助分组评测，通常没有可迁移的预测语义；model_version 可以用于分层分析，直接喂给模型则要考虑上线时的变化。

## 2. 三种“没有正反馈”具有不同含义

**曝光后未点击**：在指定点击观察窗口结束、日志足够完整的条件下，可以作为该曝光任务的 `y=0`。它表示本次条件下没有观察到点击。用户可能没看见、暂时没有需求，或者点击了相邻结果，因此不能进一步推断永久不感兴趣。

**没有曝光**：用户没有机会在该次展示中对这个物品作出反馈。召回训练可以把它抽作竞争候选，让模型区分目标物品与其他选择；这种构造提供的是对比监督。将其当成真实曝光点击率的负标签，会改变概率目标。

**暂时没有转化**：若购买仍可能在未来的归因窗口内发生，标签处于待成熟状态。过早将它记为零，会让近期样本具有更高的假负例比例，并使训练产生时间相关偏差。

这三类记录应在数据层区分。即使训练时最终都进入损失的某个负项，也要保留其来源，才能正确解释模型输出和评价结果。

搜索数据还有“未标注”这一状态。人工标注通常只覆盖部分候选，未标注文档可能相关。评测脚本如何处理未标注结果，会影响指标；训练时可用弱监督或采样策略，但需要承认额外假设。

## 3. 一条样本至少有三条时间轴

**事件时间**是行为发生的时刻。**可用时间**是系统可以消费这条记录或这个特征值的时刻。**数据构建时间**是离线任务实际生成样本的时刻。迟到日志、流处理延迟和离线回填会让它们不同。

<SearchRecDiagram kind="timeline" />

设预测发生在 `t`，某条历史特征记录的事件时间为 `t_e`、可用时间为 `t_a`。能作为输入的必要条件是：

<Equation tex={String.raw`t_e\le t,\qquad t_a\le t.`} />

例如，用户 10:00 点击了一篇文章，但行为流在 10:03 才到达推荐服务。恢复 10:01 的请求时，这个点击不能进入历史。仅按事件时间过滤，会把服务当时尚未拿到的信息带进训练。

统计特征同样需要版本。某物品“过去一天点击率”的统计区间即使截止于昨晚，统计结果也可能今天 02:00 才生成。对今天 01:00 的请求，应取更早的可用版本。今天回填计算得到的历史点击率，也不能直接冒充昨天的在线值。

这种按预测时点恢复特征的连接通常称为 **Point-in-time join**。存在多版本时，应先筛选“事件已发生且版本已可用”的记录，再根据特征语义选择最新版本。缓慢变化的用户属性、物品上下架状态和模型生成的向量，都需要类似规则。

### 标签可以使用预测之后的事件

假设目标为曝光后 `H` 小时内是否点击，标签定义为：

<Equation tex={String.raw`y_H(t)=\mathbf 1\{\exists\,t_c:\ t<t_c\le t+H,\ \text{click attributed to this impression}\}.`} />

标签使用未来观察区间是监督学习的正常做法；泄漏发生在这段未来信息进入模型输入，或者进入本应只由训练集拟合的统计量时。

为了得到可信的零标签，还需要确认窗口已结束、日志足够完整。令 `W` 为声明完整的事件时间水位，则成熟样本满足 `t+H ≤ W`。水位是一种数据完整性约定，生产中仍需监测超迟到事件及修订率，不能将墙上时钟直接当成日志完整性保证。

## 4. 点击与转化怎样关联

事件关联应优先使用明确的曝光或点击标识。若必须按用户、物品和时间匹配，就要公开匹配窗口与归因规则，并统计一对多和多对一冲突。

转化目标至少需要说明四件事：什么行为算转化、转化归到哪个触点、允许多长延迟、是否包含取消或退款。一次订单关联多个商品时，还要区分订单级、商品级和金额标签。

转化窗可以从曝光开始，也可以从点击开始。两者得到的样本成熟条件不同：

- 从曝光 `t_e` 开始，固定窗口 `H_v`：曝光达到 `t_e+H_v` 后可以判定。
- 从点击 `t_c` 开始，固定窗口 `H_v`：每次点击要等到 `t_c+H_v`。
- 点击本身也允许延迟时，要为曝光级联合标签预留点击和转化的组合观察范围，或者分别管理两类窗口。

以点击后转化为目标时，训练数据来自点击子集；以曝光后“点击且转化”为目标时，分母是曝光集合。ESMM 将点击概率和点击后转化概率相乘，在曝光空间监督点击与联合事件。[2] 比较这两种训练方式，必须使用相同的事件口径；只有点击日志的数据无法直接还原完整曝光空间。

延迟处理可以选择等待成熟、对近期未成熟数据做专门建模，或显式估计转化延迟分布。等待会损失时效，延迟模型则引入分布假设和额外估计误差。基础实验先只使用成熟数据，较容易建立可检查的基线。

## 5. 一个带时间检查的样本构造器

下面的独立示例用整数表示小时。点击窗为曝光后 2 小时，联合转化窗为曝光后 24 小时；转化必须归属于有效点击。构建任务在第 100 小时运行，日志完整性水位为第 90 小时。所有输入都已按业务事件 ID 去重。

```python
def build_samples(impressions, snapshots, clicks, conversions,
                  build_time, watermark, click_h=2, conversion_h=24):
    if not (0 < click_h <= conversion_h):
        raise ValueError("invalid observation windows")
    if watermark > build_time:
        raise ValueError("watermark cannot exceed build time")
    rows = []
    for imp in impressions:
        t = imp["time"]
        if imp["available"] > build_time:
            continue
        if t + conversion_h > watermark:
            continue  # 待成熟，后续构建时再纳入。
        visible = [
            s for s in snapshots
            if s["user"] == imp["user"]
            and s["event"] <= t and s["available"] <= t
        ]
        # 示例特征为带版本的用户状态，先按状态时间再按版本时间排序。
        latest = max(visible, key=lambda s: (s["event"], s["available"]),
                     default=None)
        valid_clicks = [
            c for c in clicks
            if c["impression"] == imp["id"]
            and t < c["time"] <= t + click_h
            and c["available"] <= build_time
        ]
        click_times = {c["id"]: c["time"] for c in valid_clicks}
        converted = any(
            v["click"] in click_times
            and click_times[v["click"]] <= v["time"] <= t + conversion_h
            and v["available"] <= build_time
            for v in conversions
        )
        rows.append({
            "id": imp["id"], "time": t,
            "feature": None if latest is None else latest["value"],
            "click": int(bool(valid_clicks)),
            "click_and_conversion": int(converted),
        })
    return rows

impressions = [
    {"id": "e1", "user": "u", "time": 10, "available": 10},
    {"id": "e2", "user": "u", "time": 20, "available": 20},
    {"id": "e3", "user": "u", "time": 75, "available": 75},
]
snapshots = [
    {"user": "u", "event": 5,  "available": 6,  "value": 2},
    {"user": "u", "event": 9,  "available": 12, "value": 7},
    {"user": "u", "event": 18, "available": 19, "value": 10},
]
clicks = [
    {"id": "c1", "impression": "e1", "time": 11, "available": 12},
]
conversions = [
    {"click": "c1", "time": 30, "available": 32},
]
rows = build_samples(impressions, snapshots, clicks, conversions, 100, 90)
assert [r["id"] for r in rows] == ["e1", "e2"]
assert rows[0]["feature"] == 2   # 值 7 在预测时尚未到达。
assert rows[0]["click_and_conversion"] == 1
assert rows[1]["feature"] == 10 and rows[1]["click"] == 0
assert all(r["click_and_conversion"] <= r["click"] for r in rows)
```

这里同时检查了特征可见性、标签事件范围和标签到达时间。实际实现通常用分区表、窗口连接和增量任务处理大规模日志；无论执行方式怎样变化，输入与标签的时间语义应保持一致。

去重应在构造器之前完成。原始传输重试一般按唯一事件 ID 去重；同一用户主动触发的多次曝光属于不同事件。可进一步监测每个曝光的点击事件数、每次转化的归因触点数，以及金额汇总在去重前后的变化。

## 6. 负采样会怎样改变数据分布

点击率较低时，保留全部正例并抽取部分负例可以降低训练成本。设正负样本保留概率分别为 `r₁、r₀`，原始点击概率为 `p`，采样后数据中的点击概率为 `p_s`，则：

<Equation tex={String.raw`p_s=\frac{r_1p}{r_1p+r_0(1-p)},\qquad \operatorname{logit}(p)=\operatorname{logit}(p_s)-\log\frac{r_1}{r_0}.`} />

推导只用了条件概率。若正例全保留、负例仅保留十分之一，训练集正例比例会显著提高。未经处理的 sigmoid 输出对应采样分布，直接作为原始曝光概率会偏高。

两条常见路线分别是：用逆保留概率加权，使训练风险对应原始目标分布；或在满足类条件随机采样假设时，对学习到的采样分布 logit 做先验修正。若训练已正确使用权重，再重复套同一修正，会引入新的偏差。

当保留概率依赖用户、物品或模型分数时，需要记录条件采样概率。一个全局常数通常无法描述它。若某类样本保留概率为零，单靠加权也无法恢复该区域的信息。

召回的负采样有另一套语义：它改变候选竞争分布和 softmax 的估计方式。<a href={withBase('blog/search-ads-rec-07-negative-sampling/')}>第七篇</a>会区分这类采样修正与曝光二分类的先验修正。

## 7. 切分方式必须对应未来使用方式

预测未来请求时，时间切分通常比逐行随机切分更贴近目标。一个可复现的做法是按预测时间分训练、验证和测试区间，再分别确保标签成熟。训练集用于更新参数，验证集用于选模型与超参数，测试集用于最终报告。

还需要检查训练时能否拿到完整标签。假设在 `T` 时刻部署模型，训练样本预测时间早于 `T`，但标签要观察到 `T+7 天` 才成熟，这部分标签不能用于模拟该次部署。可以在训练结尾留出观察间隔，或使用滚动回放：每个训练截止点仅消费当时已经可用的标签。

时间切分后，同一个用户出现在训练和测试中可能符合“服务已有用户的未来请求”这一目标。若要评价新用户泛化，就需要用户隔离的划分；评价新物品时也应采用物品隔离或按上架时间定义的冷启动集合。不同切分回答不同问题。

序列样本还要限制历史边界。目标物品发生于 `t`，历史只能包含此前可见的事件；对每个目标都从用户的完整最终历史截取一段，很容易混入未来行为。重复消费任务中，物品此前出现过可以是合法历史，但“本次目标事件”本身不能泄漏。

词表、归一化均值方差、频率截断、目标编码和负采样分布，都可能从数据中学习。它们应按实验契约用训练期数据拟合；尤其是使用标签的目标编码，需要训练内交叉拟合或严格的时间聚合，以免把样本自身标签编码进特征。

## 8. 数据质量应怎样检查

样本产出后，先检查数据是否对应预期事件，再训练模型。以下统计适合同时按日期、渠道、设备、模型版本和用户活跃度切片：

- **数量关系**：曝光量、成熟样本量、去重率、关联成功率、待成熟比例。
- **标签关系**：CTR、点击后 CVR、联合转化率，及联合正例是否都属于点击正例。
- **时间关系**：负延迟、超窗标签、事件到达延迟分位数、回填修订比例。
- **特征关系**：缺失率、OOV 比例、数值分布、序列长度、线上与离线同请求的一致率。
- **采样关系**：实际保留率、分层保留率、权重范围、加权前后标签比例。

聚合比例相近也不能保证逐条正确。可以抽取一批请求做回放，对比在线特征快照与离线恢复值，沿字段定位差异；同时追踪点击和转化的关联路径。

公开数据需要遵守其观测边界。MovieLens 主要记录评分，将评分转为隐式正反馈时必须说明阈值；未评分物品没有天然的曝光负标签。[3] Criteo 提供的点击、转化和其他数据各有字段约束，匿名化或缺失时间字段可能限制回放与切分方式。[4]

本文的代码检查了时间和关联规则，没有构成真实数据上的效果实验。得到可靠样本后，下一步需要定义评价口径：<a href={withBase('blog/search-ads-rec-03-evaluation-metrics/')}>同样的标签，哪些指标衡量概率，哪些衡量排序，哪些衡量召回</a>。
