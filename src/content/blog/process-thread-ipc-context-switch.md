## 一、核心结论

进程和线程的区别可以从“资源归属”和“调度单位”两个角度理解。

- 进程是资源分配的基本单位，有独立地址空间。
- 线程是 CPU 调度的基本单位，同一进程内线程共享地址空间。
- 进程间通信需要 IPC，因为不同进程默认不能直接访问彼此内存。
- 常见 IPC 包括管道、消息队列、共享内存、信号、Socket、文件、mmap 等。
- 线程切换比进程切换轻，但仍然有寄存器保存、调度、缓存扰动等开销。
- 高频线程切换会影响吞吐和延迟，系统设计中应尽量减少无意义阻塞和过度创建线程。

## 二、进程和线程的区别

### 进程：资源容器

一个进程通常拥有：

- 独立虚拟地址空间。
- 文件描述符表。
- 堆、栈、代码段、数据段。
- 信号处理信息。
- 一个或多个线程。

进程之间默认隔离。一个进程崩溃通常不会直接破坏另一个进程的地址空间。

### 线程：执行流

同一进程中的多个线程共享进程资源，但每个线程也有自己的执行上下文：

- 程序计数器。
- 寄存器状态。
- 线程栈。
- 线程局部存储。

可以用一个简化模型理解：

```text
Process
+--------------------------+
| Code / Heap / File Table |
|                          |
| Thread A stack           |
| Thread B stack           |
| Thread C stack           |
+--------------------------+
```

线程共享堆，因此通信更方便，但也更容易产生数据竞争。

## 三、为什么需要 IPC

不同进程有独立地址空间，不能像线程那样直接读写同一块普通内存。

```text
Process A virtual memory       Process B virtual memory
+---------------------+        +---------------------+
| address 0x1000      |        | address 0x1000      |
| means A's memory    |        | means B's memory    |
+---------------------+        +---------------------+
```

即使两个进程看到相同的虚拟地址，也不代表它们对应同一块物理内存。因此需要操作系统提供通信机制，也就是 IPC。

## 四、常见 IPC 方式

### 1. 管道 Pipe

管道适合有亲缘关系的进程之间做单向字节流通信，例如 shell 中的 `|`。

```bash
cat access.log | grep ERROR
```

`cat` 的输出通过管道传给 `grep`。

特点：

- 简单，适合流式数据。
- 普通匿名管道通常用于父子进程。
- 命名管道 FIFO 可用于无亲缘关系进程。

### 2. 消息队列

消息队列以消息为单位传递数据。

```text
Producer Process -> [ message queue ] -> Consumer Process
```

特点：

- 保留消息边界。
- 适合异步通信。
- 系统调用和数据拷贝成本通常高于共享内存。

### 3. 共享内存

共享内存让多个进程映射同一块物理内存。

```text
Process A VA ----\
                  +--> Shared Physical Memory
Process B VA ----/
```

特点：

- 速度快，避免大量数据在内核和用户态之间复制。
- 需要额外同步机制，例如信号量、互斥锁、原子变量。
- 常用于高性能数据交换。

### 4. Socket

Socket 可以用于同机进程通信，也可以跨机器通信。

```text
Process A -- TCP/Unix Domain Socket -- Process B
```

特点：

- 通用性强。
- 支持网络通信。
- Unix Domain Socket 常用于本机服务间通信。

### 5. 信号 Signal

信号用于发送简单异步通知，例如终止、暂停、用户自定义事件。

```bash
kill -TERM <pid>
```

特点：

- 信息量小。
- 适合通知，不适合传输大量数据。
- 信号处理函数中能做的事情有限。

### 6. mmap 和文件

多个进程可以通过文件或 `mmap` 映射同一文件来交换数据。

特点：

- 文件方式简单可靠，但性能受磁盘和缓存影响。
- `mmap` 可以把文件映射到内存，适合大文件或共享数据访问。

## 五、线程上下文切换是什么

线程上下文切换指 CPU 从执行一个线程切换到执行另一个线程。

简化过程：

1. 保存当前线程的寄存器、程序计数器、栈指针等状态。
2. 进入调度器，选择下一个要运行的线程。
3. 恢复下一个线程的上下文。
4. CPU 开始执行新线程。

示意图：

```text
Thread A running
    |
    | save context
    v
Scheduler chooses Thread B
    |
    | restore context
    v
Thread B running
```

上下文切换通常由时间片耗尽、线程阻塞、锁竞争、I/O 等事件触发。

## 六、上下文切换的开销来源

### 1. 保存和恢复寄存器

CPU 需要保存当前执行状态，再恢复另一个线程的状态。这部分是直接成本。

### 2. 调度器开销

操作系统需要维护可运行队列，并决定下一个运行线程。线程越多、竞争越复杂，调度成本可能越高。

### 3. CPU Cache 和 TLB 扰动

切换到另一个线程后，CPU 缓存中原本适合线程 A 的数据，可能对线程 B 没有用。

如果切换涉及不同进程，还可能影响页表和 TLB 命中率。TLB 用于缓存虚拟地址到物理地址的转换结果，失效会增加访存成本。

### 4. 用户态和内核态切换

阻塞 I/O、锁竞争、系统调用等场景可能让线程进入内核态。用户态和内核态切换本身也有成本。

### 5. 锁竞争导致的额外切换

如果很多线程争同一把锁，可能出现这样的模式：

```text
Thread A holds lock
Thread B blocks
Thread C blocks
Thread A unlocks
Scheduler wakes B
```

线程频繁睡眠和唤醒会放大上下文切换成本。

## 七、工程中的优化思路

### 1. 控制线程数量

线程不是越多越好。对于 CPU 密集任务，线程数通常接近 CPU 核数更合理。线程过多会导致调度和切换成本上升。

### 2. 使用线程池

线程池复用线程，避免频繁创建和销毁线程。

```cpp
// 简化思路：任务进入队列，固定数量 worker 线程消费任务
TaskQueue -> Worker Threads
```

### 3. 减少锁竞争

常见方式包括：

- 缩小临界区。
- 分片锁。
- 读多写少场景使用读写锁。
- 使用无锁或低锁数据结构。

### 4. 避免阻塞式等待

高性能服务中，I/O 多路复用、异步 I/O、协程等方案可以减少线程阻塞和切换。

### 5. 区分 CPU 密集和 I/O 密集

- CPU 密集：主要消耗计算资源，线程过多收益有限。
- I/O 密集：大量等待 I/O，适当增加并发可以提高吞吐。

## 八、面试回答模板

如果问题是“进程和线程有什么区别”，可以这样回答：

1. 进程是资源分配单位，线程是 CPU 调度单位。
2. 不同进程地址空间隔离，同一进程内线程共享地址空间。
3. 进程间通信需要 IPC，线程间通信可以直接共享内存，但要处理同步问题。
4. 进程切换通常比线程切换更重，因为涉及地址空间、页表、TLB 等更多状态。
5. 线程切换也有成本，包括寄存器保存恢复、调度器开销、Cache/TLB 扰动和内核态切换。

如果问题是“常见 IPC 有哪些”，可以回答：

1. 管道和 FIFO：适合字节流通信。
2. 消息队列：以消息为单位通信。
3. 共享内存：性能高，但需要同步机制。
4. Socket：通用，支持本机和跨机器通信。
5. 信号：适合简单通知。
6. 文件和 mmap：适合文件共享或大块数据映射。

## 九、总结

进程、线程和 IPC 的核心是权衡隔离性、通信成本和调度成本：

- 进程隔离性好，但通信更重。
- 线程共享内存，通信方便，但同步更复杂。
- IPC 方式越通用，通常越有额外成本。
- 线程上下文切换不是免费操作，高并发设计中要控制线程数量和锁竞争。
