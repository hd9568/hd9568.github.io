搜索、广告和推荐都在处理一个选择问题：给定当前请求，从可用对象中找出一组结果，并决定展示顺序。搜索通常带有明确的查询词；广告还要考虑投放条件、价值和预算；推荐更多依赖用户历史与当前场景。三者共享大量模型和工程方法，同时保留不同的事件定义与评价标准。

这组文章从完整链路开始，依次讨论样本、指标、特征、LR/FM、双塔、负采样和向量检索。读完后，应能沿着一条具体计算路径说明：输入何时产生，标签怎样定义，模型优化什么，输出分数如何进入候选选择。

## 1. 把一次请求写成数学问题

设 `x` 表示请求上下文，包含用户、查询、时间、设备和已经发生的行为；`i` 表示一个候选物品，在搜索中也可以是文档，在广告中可以是广告创意。模型产生分数 `s(x, i)`，系统从当前允许展示的集合中选择长度为 `K` 的列表。

<Equation tex={String.raw`\mathcal C(x)\subseteq\mathcal I,\qquad \pi=(i_1,\ldots,i_K),\qquad i_k\in\mathcal C(x)`} />

这里有三个不同层次：

- **全集 `I`**：系统收录的所有物品。删除、下架或未满足投放条件的对象仍可能存在于存储中。
- **可用集合 `C(x)`**：对当前请求具有展示资格的物品，受地域、库存、权限、预算等条件约束。
- **展示列表 `π`**：最终实际展示的有序结果；位置和相邻内容会影响用户反馈。

最简单的做法是按单物品分数取 Top-K。当列表中出现大量重复内容，或者需要限制同一作者的连续出现次数时，列表质量就很难只靠独立分数表达。更一般的目标写成：

<Equation tex={String.raw`\max_{\pi\subseteq\mathcal C(x),\,|\pi|=K} U(x,\pi)\quad \text{subject to list constraints}`} />

`U` 表示列表效用，可以包含相关性、多样性和体验等因素。这是任务表述；实际系统未必直接求解这个组合优化问题，常用逐级筛选和贪心调整得到成本可控的近似结果。

## 2. 三个场景究竟在预测什么

| 场景 | 主要输入 | 常见监督信号 | 分数的典型用途 |
| --- | --- | --- | --- |
| 搜索 | Query、文档、用户及上下文 | 人工相关性等级、点击、满意度反馈 | 找到与查询需求匹配的结果 |
| 广告 | 用户、广告、场景、投放条件 | 曝光后的点击、点击后的转化 | 估算响应概率，再结合价值与机制参与排序 |
| 推荐 | 用户历史、内容、场景 | 点击、观看、收藏、购买、负反馈 | 预测兴趣或效用，组织展示列表 |

**相关性**描述结果与需求的匹配程度。用户搜索“轻便相机”时，文档是否介绍相机、是否满足便携要求，都属于相关性问题。相关性标注可以分为多个等级，模型也可以直接学习一个无概率含义的排序分数。

**点击率 CTR**需要明确条件。以曝光为样本单位，定义点击事件 `C`、曝光事件 `E`：

<Equation tex={String.raw`\mathrm{pCTR}(x,i)=P(C=1\mid E=1,x,i)`} />

点击还受展示位置、标题、封面以及周围内容影响。用历史点击学习得到的模型，其概率解释受日志采集策略和输入字段约束。去掉位置字段，并不会自动消除位置对标签产生的影响。

**点击后转化率 CVR**以发生点击为条件。令 `V` 为在规定归因窗口内完成购买等转化事件，则：

<Equation tex={String.raw`\begin{aligned}\mathrm{pCVR}(x,i)&=P(V=1\mid C=1,E=1,x,i),\\P(C=1,V=1\mid E=1,x,i)&=\mathrm{pCTR}(x,i)\,\mathrm{pCVR}(x,i).\end{aligned}`} />

乘法来自条件概率规则。联合事件包含“点击且转化”；浏览后转化、跨设备转化等口径需要单独定义。ESMM 正是沿这个事件关系组合点击和转化任务，但模型结构本身不能保证日志归因正确。[2]

推荐中的“观看时长”又有不同性质：它是数值目标，可能存在长尾、内容长度上限与未完成观看。常见任务包括预测观看概率、条件观看时长或经过截断的效用。将它们都称为“用户喜欢的概率”，会丢失标签的实际含义。

### 一个带单位的广告例子

假设某广告按点击收费，出价为每次点击 2 元，预测点击率为 0.03。在暂时忽略机制细节和其他约束的教学假设下，每次曝光的预期点击价值为 `0.03 × 2 = 0.06` 元，对应每千次曝光 60 元。若按转化价值建模，可得到 `pCTR × pCVR × 单次转化价值`。

这些表达式用于理解期望价值和量纲。实际排序分数还可能纳入质量项、预算节奏和约束；实际扣费取决于拍卖和计费机制。预测分数、分配规则和扣费规则需要分别分析。

## 3. 候选为什么要逐级缩小

对全库每个物品执行一个昂贵模型，成本随库规模增长。级联架构先用便宜的方法找到候选，再把更多计算分配给少量结果。YouTube 2016 年的推荐论文展示了候选生成与排序两阶段架构，是理解这一分工的经典入口。[1]

<SearchRecDiagram kind="pipeline" />

用 `N` 表示全库物品数，`C₁、C₂` 表示各阶段保留的候选数。一次请求可能经历 `N → C₁ → C₂ → K`，其中通常有 `K ≤ C₂ ≤ C₁ ≪ N`。这些变量描述规模关系，具体数量由业务、延迟预算和硬件决定。

| 阶段 | 计算内容 | 可以使用的信息 | 主要失败方式 |
| --- | --- | --- | --- |
| 召回 | 倒排查找、近邻搜索、共现查表等 | 能快速筛选全库的表示与索引 | 相关结果从未进入候选 |
| 粗排 | 较轻的模型筛选候选 | 少量交互特征和较短历史 | 过早淘汰精排本可识别的结果 |
| 精排 | 候选相关的细粒度打分 | 用户、候选、历史及其交互 | 候选内顺序错误、概率失准 |
| 重排 | 在列表层面调整选择与顺序 | 单项分数、重复关系、列表约束 | 质量与多样性取舍不当 |

粗排可以作为独立阶段，也可以合并进其他阶段。候选库较小或精排足够轻时，多设一层未必划算。评估一个阶段的价值，要看它节省了多少后续计算，以及多损失了多少相关候选。

这里存在不可逆的遗漏：精排只能处理已经收到的候选。若召回集合里没有目标文档，再强的精排模型也无法把它放进最终列表。因此需要分别报告候选覆盖和候选内排序质量。

设 `R(x)` 为相关集合，`A(x)` 为召回集合，则最终列表中的相关物品数至多为 `|R(x) ∩ A(x)|`。这个简单上界解释了为什么只观察最终 NDCG 很难定位问题：遗漏可能来自召回，也可能来自后续筛选。

## 4. 多路召回各自补充什么

单一路径的表达能力有限，实际系统常把多个召回集合合并、去重并附带来源信息。

**词项召回**依赖倒排索引，能直接匹配名称、型号和专业术语。BM25 根据词频、文档长度和词的区分能力计算匹配分数。它对精确词面需求很有价值，分词、同义词和查询改写会显著影响覆盖。

**向量召回**把请求与物品编码为向量，用内积或余弦相似度检索。它可以表达训练中学到的语义或兴趣关系，同时受表示容量、训练样本和索引近似影响。本系列后半部分会完整展开。

**协同召回**利用群体交互关系，例如购买过相同商品的人还购买了哪些商品。它能发现内容字段中难以直接读出的关联，但新用户和新物品的历史较少。

**热门、规则与运营集合**可以覆盖历史不足或模型失效的情况，也可能承担内容时效与特殊约束。评价时应记录这类候选的来源，才能判断质量来自模型还是其他通道。

多个通道的原始分数通常量纲不同。BM25 分数、向量内积和点击概率不能直接相加。可采用分通道配额、基于排名的融合或训练统一融合模型，并在固定候选预算下比较质量。分配更多名额给某一路，会改变其余通道的覆盖空间。

## 5. 排序模型如何从输入走到分数

排序模型常把离散 ID 映射为 Embedding，把数值特征做归一化，再通过交互层或神经网络得到输出。Embedding 是可学习的向量表；相同 ID 查到同一行，训练通过梯度更新这行参数。

从结构上看，可以沿以下关系理解常见模型：

- **LR**对输入特征做线性加权，再用 sigmoid 得到二分类概率。它是检验特征、标签与训练流程的直接基线。
- **FM、DeepFM、DCN**引入不同形式的特征交互，表达“同一特征在不同条件下作用不同”。例如某个类目对不同兴趣群体的点击倾向不同。
- **DIN 等兴趣模型**用当前候选参与历史行为聚合。相机候选可能更关注摄影历史，跑鞋候选可能更关注运动历史。
- **序列模型**保留行为顺序和时间关系，表达近期意图及兴趣变化。
- **多任务模型**共享部分表示，同时预测点击、转化、观看等目标。共享能增加监督，也可能因目标冲突产生负迁移。

这些维度可以组合。一个排序模型可以同时包含离散特征、候选相关历史聚合和多个预测头。讨论结构时，最好画出每一路输入如何到达输出，再判断共享发生在哪里。[3][4]

若一个请求有 `C` 个候选，每个候选需要长度为 `L` 的历史交互，某些计算会随 `C×L` 增长。用户侧可复用的编码与候选相关的计算分开后，才能判断批处理、缓存或模型压缩能节省哪部分成本。

## 6. 日志把线上系统与训练连接起来

模型只观察到系统记录的事件。一次请求进入系统后，会经过资格过滤、召回和排序；用户只看到其中少量内容。训练日志因此带有旧策略的选择结果。

一条可以解释的曝光记录至少需要关联请求、用户、物品、位置、时间和策略版本。点击和转化通过事件关联写回标签，特征则必须按预测时刻恢复。以下三件事分别影响训练可靠性：

1. **样本单位**：一条样本代表一次曝光、一次点击，还是一对 Query—文档。重复曝光不能在没有规则时随意合并。
2. **信息时点**：历史和统计特征只使用预测时已经可得的数据；标签可以来自预测后的观察窗口。
3. **选择过程**：曝光未点击和从全库抽取的未曝光物品，具有不同的监督含义。

当模型上线改变曝光分布后，下一轮训练数据也会改变。这形成反馈闭环：已经得到曝光的物品更容易积累数据，长尾物品可能持续缺少观察。随机探索、反事实评价和实验设计分别提供不同帮助，但都依赖明确的采集条件，不能只靠换一个网络消除反馈偏差。

## 7. 重排：把候选分数组织成列表

下面用一个独立可运行的小例子说明类别上限。输入分数是假设值，约束是“最多展示三个结果，每个类别最多两个”。代码只是确定性规则演示，没有学习用户效用。

```python
from collections import Counter

def rerank_with_category_cap(candidates, k, max_per_category):
    if k < 0 or max_per_category < 1:
        raise ValueError("invalid list constraints")
    counts = Counter()
    selected, seen = [], set()
    # 同分按 ID 排序，便于复现；不会重复展示同一物品。
    for item in sorted(candidates, key=lambda x: (-x["score"], x["id"])):
        if len(selected) == k:
            break
        if item["id"] in seen:
            continue
        seen.add(item["id"])
        category = item["category"]
        if counts[category] >= max_per_category:
            continue
        selected.append(item)
        counts[category] += 1
    return selected

candidates = [
    {"id": 1, "category": "camera", "score": 0.93},
    {"id": 2, "category": "camera", "score": 0.91},
    {"id": 3, "category": "camera", "score": 0.89},
    {"id": 4, "category": "lens",   "score": 0.85},
]
chosen = rerank_with_category_cap(candidates, k=3, max_per_category=2)
assert [item["id"] for item in chosen] == [1, 2, 4]
assert rerank_with_category_cap(candidates, k=0, max_per_category=2) == []
```

约束把第三个相机替换为镜头，列表类别覆盖随之增加，但原始分数总和下降。这个例子只能证明规则按预期执行。要判断用户体验是否改善，还要结合相关性、重复程度、负反馈和线上实验。

类别上限也可能让返回结果少于 `K`。是否允许放松上限、由哪个通道补充、何时返回短列表，属于需要明确的产品和系统规则。把这些策略隐含在代码中，会使离线评价与线上行为难以对齐。

## 8. 质量与成本怎样一起评价

离线评价可以分为三层：概率预测用 LogLoss、校准等指标；候选内排序用 AUC、NDCG 等指标；候选生成用 Recall@K 等指标。线上实验进一步观察用户行为及收益，同时设置延迟、错误率、投诉或负反馈等护栏。

执行成本也需要分层记录。请求总延迟可能包含特征获取、远程调用、排队、模型计算和结果合并。顺序执行的阶段会累加延迟，并行分支通常受最慢分支和汇合方式影响。平均耗时无法反映少量请求的长尾，P99 表示 99% 的观察请求不超过该值，统计时需要说明窗口和负载条件。

模型吞吐提高后，如果请求仍主要等待特征服务，总体延迟可能变化很小。相反，减少候选数可能同时降低特征拉取、网络传输和模型计算，却损失召回覆盖。应先分解链路，再决定优化目标。

一个完整实验至少固定数据窗口、候选来源、模型版本和评价口径。可以逐层替换召回或排序模块，记录候选覆盖、最终质量和执行成本。若同时改了特征、负例和候选数，就很难将收益归因到某个模型结构。

## 9. 用一条商品请求串起后续学习

用户搜索“轻便相机”时，词项通道找出直接匹配的商品，向量通道补充语义或兴趣相近的结果；资格过滤排除不可售商品；排序模型结合查询、商品、用户历史估计相关性或交互概率；重排控制重复并组织列表；曝光、点击和购买再成为后续训练记录。

沿这条链路，可以依次问出后续七篇的问题：一行训练数据对应哪个事件；未点击如何标注；概率和排名怎样评价；ID 与历史怎样进入网络；LR/FM 怎样表达交互；双塔怎样独立编码；负例改变了什么目标；向量索引又损失了哪些候选。
